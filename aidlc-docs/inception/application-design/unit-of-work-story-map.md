## 기반 유닛(Unit 1) 소유 항목
Unit 1은 특정 사용자 스토리가 아닌 **횡단(cross-cutting) 기반**을 소유하며, 아래 요구사항의 데이터/계약 측면을 담당한다.

| 관련 요구사항 근거 | Unit 1 소유 산출물 |
|---|---|
| 3.1.4 주문 정보 항목, 부록 A 테이블 세션 정의 | 도메인 모델(Store/Table/TableSession/Order/OrderItem 등) |
| 3.2.3 데이터 관리(OrderHistory, 세션 ID 그룹화, 완료 시각) | OrderHistory 스키마, 세션 판별·총액 계산 규칙 |
| 3.2.2 SSE 기반 실시간 통신 | SSE 이벤트 계약 및 공통 브로커 모듈 |
| 전반 | SQLite 스키마·마이그레이션, API 계약 초안, 표준 에러 포맷, 모노레포 스캐폴딩 |

## 커버리지 검증
- 고객용 기능 3.1.1 ~ 3.1.5: **전부 Unit 2에 배정** ✔
- 관리자용 기능 3.2.1 ~ 3.2.4: **Unit 3(3.2.1, 3.2.2), Unit 4(3.2.3), Unit 5(3.2.4)에 배정** ✔
- 모든 기능 요구사항이 정확히 하나의 기능 유닛에 배정됨(중복·누락 없음).
- 횡단 기반(모델·스키마·계약·SSE)은 Unit 1이 단일 소유.

## 제외 범위 확인
`requirements/constraints.md`의 제외 기능(결제, OAuth/2FA, 이미지 최적화, 알림, 주방, 분석/리포트, 외부 연동 등)은 어떤 유닛에도 배정하지 않는다.
