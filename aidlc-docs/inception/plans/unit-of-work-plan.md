# Unit of Work Plan (유닛 분할 계획) — 테이블오더 서비스

## 목적
5명의 개발자(김주영, 박찬준, 임동규, 이명우, 윤태경)가 **병렬로** 개발할 수 있도록 시스템을 **5개의 유닛**으로 분할하고, 각 유닛의 책임·경계·의존성·개발자 배정을 확정합니다.

**기술 스택 (확정됨)**: Python 백엔드 · Vue 프론트엔드 · SQLite · 로컬 실행 · 모노레포 · SSE

---

## 분할 원칙
1. **도메인 응집도**: 관련된 기능을 하나의 유닛으로 묶음
2. **의존성 최소화**: 병렬 개발을 위해 유닛 간 결합을 낮추고, 공유되는 기반(DB 스키마/모델/인증)은 계약(interface)으로 조기 확정
3. **균등한 작업량**: 5명에게 비슷한 규모의 작업이 돌아가도록 배분
4. **명확한 소유권**: 유닛당 1명의 주 담당 개발자

---

## 제안하는 5개 유닛 분할 (초안)

> 아래는 요구사항 문서 기반 초안입니다. 질문 섹션에서 확정/수정해 주세요.

### Unit 1: Foundation & Shared Core (공통 기반)
- **책임**: 프로젝트 스캐폴딩(모노레포 구조), SQLite 스키마 및 마이그레이션, 공유 데이터 모델(Store/Table/Menu/Order/OrderHistory/Session), 공통 유틸(에러 응답 포맷, DB 접근 계층), API 계약(OpenAPI/스키마) 초안, SSE 인프라 공통 모듈
- **포함 요구사항**: 데이터 저장소 전반, 세션/주문 데이터 모델, OrderHistory 테이블 구조
- **비고**: 다른 모든 유닛이 의존하는 기반. **가장 먼저 계약을 확정**해야 병렬 개발이 원활

### Unit 2: Customer Ordering (고객 주문 - 프론트+백엔드)
- **책임**: 고객용 웹UI 및 관련 API — 테이블 태블릿 자동 로그인/세션, 메뉴 조회·탐색(카드 UI, 카테고리), 장바구니 관리(로컬 저장), 주문 생성(성공 플로우/자동 리다이렉트), 현재 세션 주문 내역 조회
- **포함 요구사항**: 3.1.1 ~ 3.1.5 (고객용 기능 전체)

### Unit 3: Admin Auth & Real-time Monitoring (관리자 인증 + 실시간 모니터링)
- **책임**: 관리자 매장 인증(JWT, 16시간 세션, bcrypt, 로그인 시도 제한), 실시간 주문 모니터링(SSE 소비, 그리드/대시보드 레이아웃, 테이블별 카드, 신규 주문 강조, 주문 상세 보기, 상태 변경, 테이블 필터링)
- **포함 요구사항**: 3.2.1 매장 인증, 3.2.2 실시간 주문 모니터링

### Unit 4: Table & Session Management (테이블·세션 관리)
- **책임**: 테이블 태블릿 초기 설정(번호/비밀번호, 16시간 세션 생성), 주문 삭제(직권 수정, 총액 재계산), 테이블 세션 라이프사이클(시작/종료, 이용 완료 처리, 이력 이동, 총액 리셋), 과거 주문 내역 조회(날짜 필터)
- **포함 요구사항**: 3.2.3 테이블 관리 (초기 설정, 주문 삭제, 세션 처리, 과거 내역)

### Unit 5: Menu Management (메뉴 관리)
- **책임**: 관리자 메뉴 CRUD(등록/수정/삭제/조회), 카테고리 관리, 노출 순서 조정, 데이터 검증(필수 필드, 가격 범위), 관련 관리자 UI
- **포함 요구사항**: 3.2.4 메뉴 관리

## 개발자 배정 (초안)
| 유닛 | 개발자 | 비고 |
|---|---|---|
| Unit 1: Foundation & Shared Core | 김주영 | 기반 유닛 — 계약 조기 확정 필요, 초기 리드 역할 |
| Unit 2: Customer Ordering | 박찬준 | 프론트+백엔드 풀스택 |
| Unit 3: Admin Auth & Monitoring | 임동규 | 인증 + SSE 실시간 |
| Unit 4: Table & Session Mgmt | 이명우 | 세션 라이프사이클 |
| Unit 5: Menu Management | 윤태경 | CRUD 중심 |

---

## 의존성 (초안)
- Unit 2, 3, 4, 5 → **모두 Unit 1(Foundation)에 의존** (공유 모델/스키마/API 계약)
- Unit 3(모니터링) ← Unit 2(주문 생성 이벤트), Unit 4(세션/삭제 이벤트)의 SSE 이벤트 소비
- Unit 4(세션 종료) → Unit 2(고객 주문 내역 필터링)와 세션 개념 공유
- Unit 5(메뉴) → Unit 2(고객 메뉴 조회)가 데이터 소비
